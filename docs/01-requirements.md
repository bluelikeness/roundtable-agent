# 멀티봇 허브 요구사항 정의서

> 작성일 2026-11-08

## 1. 개요

메타 뮤즈, 피클, Vooy 같은 소비자용 AI 에이전트 봇들을 하나의 웹 허브에서 다루고, Claude가 그 가운데서 질문을 배분하고 답을 정리하며 봇끼리 대화를 잇는 오케스트레이터 역할을 한다. Claude 호출은 서버에 내 계정으로 로그인한 Claude Code를 헤드리스(claude -p)로 띄우는 방식이고, 봇 어댑터는 MCP 서버로 Claude Code에 붙는다.

세 봇 모두 공식 개발자 API가 없다. Vooy는 텔레그램을 서비스 채널로 쓰고, 뮤즈는 muse.ai 웹과 모바일 앱, 피클은 iPhone·Android 앱만 제공한다. 따라서 허브는 각 봇에 맞는 비공식 연결 경로(어댑터)를 두고, 그 위에서 Claude가 판단하는 구조다.

이 문서는 요구사항까지만 정의한다. 아키텍처·어댑터·오케스트레이터 설계는 별도 문서로 이어지고, 구현은 Claude Code로 진행한다.

## 2. 범위

**사용자**: 나 혼자. 봇 계정(텔레그램·메타·피클)은 내 계정이고, Claude는 서버에 내 계정으로 로그인한 Claude Code를 헤드리스로 호출해 내 구독으로 쓴다. 지인 공유는 범위 밖이다. 구독 Claude Code로 타인 트래픽을 처리하는 것은 Anthropic 약관 위반이라, 공유하려면 Claude 호출을 운영자 API 키 방식으로 바꿔야 한다.

**실행 환경**: 클라우드 서버에 상시 구동. 웹 UI는 PC·모바일 브라우저 모두 지원한다. 피클 어댑터처럼 안드로이드 에뮬레이터가 필요한 부분은 별도 워커로 분리할 수 있어야 한다.

**대상 봇 (초기 3개)**

| 봇 | 제공 형태 | 연결 경로 (예정) | 지역 제약 |
| --- | --- | --- | --- |
| Vooy | 텔레그램 + Android/iOS 앱 | 텔레그램 유저 세션 | 없음 |
| 메타 뮤즈 | 앱 + muse.ai 웹 + WhatsApp | muse.ai 브라우저 자동화 | 미국·캐나다·일본·싱가포르만 |
| 피클 | iPhone·Android 앱 | 안드로이드 에뮬레이터 UI 자동화 | 없음 (앱 자체는 한국 사용 가능) |

**범위 밖**

- 봇이 수행하는 실제 작업(결제·예약 등)의 결과 보증. 허브는 대화만 중계한다.
- 각 봇의 계정 생성·결제·지역 우회. 운영자가 사전에 준비한다.
- 지인·타인 사용. 열게 되면 Claude 호출 계층만 API 키 방식으로 교체하고, 봇 계정도 사용자별로 분리해야 한다.

## 3. 사용 시나리오

사용자는 모드를 고르지 않는다. 자연어로 말하면 Claude가 시나리오를 판단한다.

| # | 시나리오 | 사용자 입력 예 | Claude 동작 | 결과 표시 |
| --- | --- | --- | --- | --- |
| S1 | 단일 봇 질의 | "Vooy한테 이번 주말 강남 맛집 찾아달라고 해" | 지목된 봇 1개 호출 | 원문 + 한 줄 요약 |
| S2 | 팬아웃 비교 | "셋 다한테 도쿄 왕복 항공권 최저가 물어봐" | 3개 병렬 호출, 답 비교 | 봇별 원문 + Claude 비교표 |
| S3 | 릴레이 | "Vooy가 찾은 식당을 뮤즈한테 예약 가능한지 확인시켜" | 순차 호출, 앞 봇 답을 뒤 봇 입력으로 변환 | 단계별 원문 + 최종 정리 |
| S4 | 봇 간 토론 | "뮤즈랑 피클이 서로 추천안 비판하게 해봐" | 라운드 반복, Claude가 종료 판단 (기본 3라운드 상한) | 라운드별 원문 + 결론 |
| S5 | 이어지는 대화 | "아까 Vooy가 말한 두 번째 식당 예약해줘" | 이전 세션 맥락 유지, 해당 봇 재호출 | 원문 + 요약 |
| S6 | 봇 장애 | 뮤즈 로그인 만료 상태에서 S2 요청 | 가용 봇만 호출, 장애 봇은 명시적으로 알림 | 가용 봇 원문 + "뮤즈 응답 불가: 로그인 만료" |
| S7 | Claude 단독 답변 | "오케스트레이터 구조 설명해줘" | 봇 호출 없이 직접 답변 | Claude 답변만 |

모든 시나리오에서 Claude는 어떤 봇을 왜 호출했는지 한 줄로 밝힌다. 사용자가 "Vooy만"처럼 명시하면 Claude 판단보다 우선한다.

## 4. 기능 요구사항

우선순위: M = 1차 필수, S = 1차 권장, C = 이후.

**오케스트레이션 (Claude)**

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-01 | 사용자 메시지를 읽고 호출할 봇·순서(병렬/순차)를 Claude Code(헤드리스)가 결정한다. 어댑터는 MCP 툴로 노출된다 | M |
| FR-02 | 사용자가 봇을 명시하면 그 지시가 Claude 판단보다 우선한다 | M |
| FR-03 | 여러 봇 답을 받으면 원문을 그대로 보여주고, 그 아래 Claude의 비교·정리를 붙인다 | M |
| FR-04 | 릴레이 시 앞 봇의 답을 뒤 봇이 이해할 입력으로 변환한다 (봇 이름·맥락 포함) | M |
| FR-05 | 봇 간 토론은 라운드 상한(기본 3)과 Claude의 종료 판단으로 끝낸다 | S |
| FR-06 | 대화 세션 안에서 이전 봇 답변을 참조해 후속 질의를 할 수 있다 | M |
| FR-07 | 어떤 봇을 왜 호출했는지 한 줄로 표시한다 | S |

| FR-12 | 어댑터별 직렬 큐. 브라우저·기기를 점유하는 봇은 동시에 한 요청만 처리한다 | M |

## 5. 비기능 요구사항

| ID | 항목 | 기준 |
| --- | --- | --- |
| NFR-01 | 응답 지연 | 봇 응답은 UI 자동화 특성상 수십 초가 걸릴 수 있다. 어댑터 타임아웃 기본 120초(재시도 포함), 초과 시 실패로 처리하고 다른 봇 답은 먼저 보여준다 |
| NFR-02 | 부분 실패 허용 | 봇 1개가 실패해도 나머지 봇 답과 Claude 정리는 정상 표시된다 |
| NFR-03 | 상태 스트리밍 | 봇별 진행 상태와 Claude 답변은 WebSocket으로 실시간 전달된다 |
| NFR-04 | 세션 보존 | 허브 대화 이력은 영구 저장. 봇 쪽 대화 스레드는 봇 정책에 따르며 허브가 보증하지 않는다 |
| NFR-05 | 동시성 | 어댑터별 직렬 큐. 팬아웃 시 어댑터 간은 병렬, 어댑터 안은 순서대로 처리하고 대기 상태를 UI에 표시한다 |
| NFR-06 | 인증·접근 | 허브 로그인 필수. 외부에 공개하지 않으며, 로그인 없이는 어떤 엔드포인트도 응답하지 않는다 |
| NFR-07 | 자격증명 보관 | 텔레그램 세션, 메타 로그인 쿠키, 피클 로그인 상태, Claude Code 로그인 토큰은 암호화해 서버에만 보관하고 UI·로그에 노출하지 않는다 |
| NFR-08 | 로그 보존 | 요청·응답 로그 90일 보존. 봇 원문에 개인정보가 섞일 수 있으므로 운영자만 조회 |
| NFR-09 | 복구 | 어댑터 장애 시 자동 재시도 1회, 실패하면 비활성 전환 후 운영자에게 알림. 재로그인은 수동 |
| NFR-10 | 확장성 | 봇 추가 시 코드 변경은 어댑터와 설정 파일로 한정. 어댑터는 허브와 별도 프로세스·서버에서 돌 수 있어야 한다 (피클용 맥 워커 대비) |
| NFR-11 | 비용 | Claude 비용은 내 구독 한도 안에서 쓴다. 호출은 메시지당 Claude Code 실행 1회(툴 호출 포함)를 목표로 하고, 토론 모드는 라운드 상한으로 제한한다 |
| NFR-12 | 배포 | 컨테이너 기반. 허브·웹·각 어댑터 워커를 개별 배포 가능 |

## 6. 제약 및 리스크

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| 비공식 연결 경로가 각 봇의 약관을 위반할 수 있다 | 계정 정지, 봇 사용 불가 | 내 계정만 걸린다. 요청 빈도 제한, 전용 텔레그램·메타 계정 분리 |
| 뮤즈가 한국 미지원 | 해외 계정·VPN 없이는 어댑터 불가 | 1차 범위를 S로 두고, 확보 안 되면 Meta Model API 기반 "뮤즈 대체 봇"으로 대신한다 |
| 피클은 모바일 앱뿐 (iOS·Android) | 서버에 에뮬레이터 상시 구동(RAM 2\~4GB) 필요. 앱 업데이트마다 자동화 깨짐 | 1차 범위 S. 에뮬레이터에서 피클 로그인·동작이 막히지 않는지 먼저 확인 |
| 텔레그램 유저 세션 자동화 | 비정상 패턴 감지 시 계정 제한 | 전용 텔레그램 계정 사용, 메시지 간격 제한 |
| 봇 응답 형식이 비정형 (버튼, 카드, 이미지) | 텍스트만 추출하면 정보 손실 | 어댑터가 원문 + 구조화 데이터(버튼 목록, 링크)를 함께 반환 |
| 봇이 되묻는 경우 ("몇 명이세요?") | 릴레이가 멈춤 | Claude가 되물음을 감지해 사용자에게 전달하거나 맥락으로 대답 |
| Claude Code 헤드리스 자동화 정책 | 개인 자동화 범위를 벗어나거나 정책이 바뀌면 호출 방식 교체 필요. 토론 모드는 구독 한도를 빨리 소진 | 나 혼자만 사용. Claude 호출 계층을 분리해 API 키 방식으로 교체 가능하게 설계. 라운드 상한, 봇 원문 길이 제한 |

## 7. 미결 사항

- [ ] Vooy 봇이 텔레그램 1:1에서 안정적으로 응답하는지, 그룹에서도 되는지 실제 확인
- [ ] 한국에서 muse.ai 계정 생성·로그인이 되는지 확인. 안 되면 해외 계정 확보 방법 결정
- [ ] 피클 Android 앱이 에뮬레이터(루팅 아님)에서 정상 로그인·동작하는지 확인
- [ ] 에뮬레이터를 상시 구동할지, 요청 시에만 띄우고 로그인 상태를 스냅샷으로 보존할지 결정
- [ ] 허브 대화 이력의 보존 기간과 삭제 정책
- [ ] 클라우드 서버 사양·비용 상한
- [ ] Claude Code 약관 페이지에서 헤드리스 개인 자동화 허용 범위 직접 확인
- [x] Claude Code 헤드리스 세션(--resume)을 허브 세션과 1:1로 둘지, 메시지마다 새로 띄우고 맥락을 허브가 넘길지 결정 — 1:1 + `--resume` (아키텍처 ADR-2)
