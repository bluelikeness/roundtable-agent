# 설계 변경안: 휴대폰 워커 (에뮬레이터·VM 2 대체)

> 작성일 2026-11-11 · 상태: **승인(2026-11-11)** · 02·03·06의 해당 절에 반영했다. 이 문서는 ADR-9의 근거로 남는다.

## 1. 결론

Vooy·피클·뮤즈를 서버의 에뮬레이터·브라우저로 조종하지 않는다. **사용자의 안드로이드 휴대폰에 설치한 워커 앱**이 세 앱을 접근성 서비스로 조종하고, 일반 인터넷으로 허브에 **바깥으로(아웃바운드) 연결**한다. 허브 쪽에는 휴대폰과 통신하는 **폰 게이트웨이**를 두고, 그 안에 기존 계약 그대로의 MCP 어댑터 3개(vooy·pickle·muse)를 둔다. 허브 API·러너·웹·어댑터 MCP 계약은 바뀌지 않는다.

## 2. 근거 (2026-11-11 실측)

시험 앱(`tools/phone-probe`)으로 실제 휴대폰에서 측정했다. 질문 1건 기준.

| | Vooy | 피클 | 뮤즈 (`com.facebook.aura`) | 참고: 에뮬레이터 Vooy |
| --- | --- | --- | --- | --- |
| 입력 | 접근성 `SET_TEXT` 성공 | 성공 | 성공 | 성공 |
| 전송 | 라벨 "메시지 전송" | "보내기" | `hatch-send-button` | "Send message" |
| 보내고 홈으로 나가기까지 | 6.2초 | 5.9초 | 6.2초 | 62초 |
| 답 알림 | 1개 (+11.8초, 말풍선 3개를 묶음) | 말풍선마다 1개 (+4.3초, +9.8초) | "작업 중" 알림 +1초 → 끝나면 답 알림 +17초 | — |
| 알림 눌러 앱 열기 | 실패 | 실패 | 실패 | 실패 |
| 앱 직접 열기(런처 인텐트) | 성공 | 성공 | 성공 | 성공 |
| ask 1건 전체 | 37초 | 35초 | 27초 | 약 2분 |

- 알림을 눌러 여는 방식은 안드로이드의 백그라운드 활동 시작 제한(BAL)에 막힌다. 앱은 런처 인텐트로 연다.
- Vooy는 마지막에 보던 탭으로 열린다. 입력창이 없으면 하단 vooy 탭(`android-gnb-home`)을 먼저 누른다.
- 휴대폰 Vooy는 한국어 UI라 라벨이 "메시지 입력"·"메시지 전송"이다. 하단 탭 라벨 "vooy 탭, 대기 중"은 응답 중 표시 후보다.
- 뮤즈 답 알림에는 답장 입력(RemoteInput)이 있다. 이어지는 질문은 앱을 열지 않고 보낼 수 있을 가능성이 있다(미확인).

## 3. 구조

```
[웹 UI] ─ [허브 API] ─ [러너: claude -p] ─MCP(HTTP)─▶ [폰 게이트웨이]
                                                     ├ vooy 어댑터 (MCP :9000/vooy, 관리 :9100/vooy)
                                                     ├ pickle 어댑터
                                                     ├ muse 어댑터
                                                     └ 휴대폰 연결 관리(기기 잠금·명령 중계)
                                                            ▲
                                       wss://<허브 도메인>/phone/ws  (휴대폰이 바깥으로 연결)
                                                            │
                                                  [휴대폰 워커 앱]
                                                  ├ 접근성 서비스: 앱 열기·노드 찾기·입력·탭·화면 읽기
                                                  ├ 알림 리스너: 대상 앱 알림을 즉시 게이트웨이로
                                                  └ 포그라운드 서비스: 연결 유지·재연결
```

**역할 나누기: 휴대폰은 손, 게이트웨이는 머리.**

- 휴대폰 워커는 봇을 모른다. "이 앱을 열어라, 이 조건의 노드를 찾아 눌러라, 화면 트리를 보내라" 같은 범용 명령만 수행하고, 알림을 이벤트로 올린다.
- 봇별 지식(셀렉터, 말풍선 구분, 응답 확정 규칙, `[tap:]`)은 전부 게이트웨이의 Python 어댑터에 있다. 앱이 바뀌면 서버의 `selectors.yaml`만 고치고 APK는 다시 깔지 않는다.
- 지금의 `android_base`(uiautomator2) 자리에 "원격 손" 클라이언트가 들어간다. `UiNode`·셀렉터 규칙·말풍선 수집 로직은 그대로 재사용한다.

## 4. 연결: 일반 인터넷, 휴대폰이 바깥으로

- 휴대폰은 들어오는 연결을 받지 않는다. 워커가 `wss://<허브 도메인>/phone/ws`로 연결하고 끊기면 지수 백오프로 다시 붙는다. 이동통신망·와이파이 어디서나 같다.
- 허브는 공개 HTTPS가 필요하다. 02 7장의 VM 1 + Caddy(443)를 그대로 쓰고, Caddy에 `/phone/ws` → 폰 게이트웨이 경로 하나를 더한다. 허브 API 코드는 바뀌지 않는다.
- 인증: 기기 토큰(긴 무작위 문자열). 게이트웨이가 발급하고 QR로 휴대폰에 넣는다(`scripts/phone-pair`). 웹 UI에 페어링 화면을 두는 건 범위 밖(웹 변경이므로 별도 결정).
- 하트비트 15초. 30초 넘게 끊기면 게이트웨이는 세 어댑터의 `status`를 `available=false, reason=backend_down`으로 바꾸고 허브 웹훅을 부른다.
- 개발 중(허브가 개발 PC에 있을 때)은 공개 주소가 없다. 사용자가 직접 띄우는 임시 터널이나 VM 1 선배포가 필요하다(8장 미결).

## 5. 휴대폰 명령 프로토콜 (요약)

JSON 메시지, 요청마다 `id`. 게이트웨이 → 휴대폰:

| 명령 | 인자 | 결과 |
| --- | --- | --- |
| `state` | — | 화면 켜짐·잠금·전경 앱·배터리·워커 버전 |
| `launch` | `pkg` | 전경이 된 시각 |
| `tree` | `pkg`, `max_nodes` | 노드 목록(class·id·desc·text·bounds·clickable·editable) |
| `find` / `click` / `set_text` / `paste` | 셀렉터(`id`·`desc`·`text`·`class`, 정규식 허용) 또는 좌표 | 성공 여부, 대상 노드 |
| `global` | `home` · `back` | — |
| `watch` | `pkgs` | 이후 알림 이벤트 구독 |

휴대폰 → 게이트웨이 이벤트: `notif.posted` / `notif.removed`(패키지·채널·형식·제목·본문·메시지 목록·시각), `state.changed`.

트리와 알림 본문은 사용자 자신의 허브로만 간다. 게이트웨이는 03 5장 `/logs`에 본문 앞 40자 외에는 남기지 않는다.

## 6. ask 흐름 (게이트웨이 어댑터)

1. **보내기** (화면 사용): 기기 잠금 획득 → `state` 확인(잠금·꺼짐이면 `unavailable`) → `launch` → 입력창 없으면 대화 탭 이동 → `set_text` → 전송 버튼 `click` → 내 말풍선 확인 → `global home` → 기기 잠금 해제.
2. **기다리기** (화면 안 씀): 해당 패키지 알림 이벤트를 기다린다. 봇별 끝 판정:
   - 피클: 말풍선마다 알림. 마지막 알림 뒤 `quiet_s`.
   - Vooy: 알림이 묶여 1개. 첫 알림 뒤 `quiet_s`를 길게(예 8초) 둔 다음 읽기에서 확정.
   - 뮤즈: "작업 중" 알림(`aura_run_in_background`)이 사라지고 답 알림이 오면 끝.
   - 알림이 `timeout_s` 절반까지 없으면 3으로 넘어가 화면에서 직접 확인(기존 폴링 방식으로 후퇴).
3. **읽기** (화면 사용): 기기 잠금 → `launch` → `tree` → 내 질문 말풍선 아래의 새 말풍선·버튼 추출(기존 `_collect`·`_extract` 규칙) → 응답 중 표시가 있으면 한 번 더 → `home` → 해제.

화면을 쓰는 1·3만 기기 잠금으로 직렬화한다. 2는 봇 셋이 동시에 기다릴 수 있다. 어댑터 큐(봇당 직렬)는 그대로다.

## 7. 휴대폰 요건과 운영

- **봇 전용 공기계를 권장한다.** 개인 휴대폰이면 조종 중(질문당 화면 사용 약 10초 × 2회) 사용자 조작과 부딪히고, 개인 알림·대화가 트리에 섞인다.
- 화면이 잠겨 있으면 조종할 수 없다. 공기계는 충전기에 꽂고 "충전 중 화면 켜짐" + 잠금 없음으로 둔다. 개인 폰이면 잠긴 동안 세 봇이 `unavailable`이 된다.
  - 2026-11-12 화면 깨우기: 보안 잠금(PIN·패턴·지문)이 없으면(잠금 없음·밀어서 해제) 화면이 꺼져 있어도 가용이다. 봇이 화면 임대를 받을 때 워커가 화면을 켜고 잠금화면을 넘긴다(명령 `wake`: 잠금화면 위 투명 화면 + 넘기기 요청, 안 되면 위로 밀기). 우리가 켠 화면은 임대가 모두 끝나고 `PHONE_SCREEN_OFF_AFTER_S`(기본 30초, 0 이면 끄지 않음) 뒤 다시 끈다. 사람이 켠 화면은 끄지 않는다. 보안 잠금이 있으면 깨우지 않고 지금처럼 `unavailable`이다. 그래서 "충전 중 화면 켜짐"은 필요 없다
- 로그인: 사용자가 휴대폰에서 각 앱에 직접 로그인한다. noVNC 로그인 시트는 필요 없다. 앱이 로그아웃되면 어댑터가 `login_required`를 보고하고, 재로그인은 휴대폰에서 직접 한다(5장 `/login/start` 처리는 8장 미결).
- 워커 앱 배포: 직접 빌드한 APK(사이드로드). 접근성·알림 권한은 "제한된 설정 허용" 후 켠다(안드로이드 13+). 앱 업데이트는 드물게 하도록 워커를 얇게 유지한다.

## 8. 기존 설계에서 바뀌는 곳

| 문서 | 절 | 변경 |
| --- | --- | --- |
| 02 | 1·2장 | 어댑터가 조작하는 채널: "에뮬레이터·웹" → "휴대폰 워커 경유 앱". 컴포넌트 표에 휴대폰 워커·폰 게이트웨이 추가, Vooy·피클·뮤즈 행의 기술 교체 |
| 02 | 5장 봇별 표 | `_send`·`_collect`를 6장 흐름으로 교체. 뮤즈는 Playwright·VPN 대신 Meta AI 앱(`com.facebook.aura`) |
| 02 | 7장 | VM 2·WireGuard·noVNC·VPN 사이드카 삭제. VM 1에 `phone-gateway` 컨테이너 추가, Caddy 경로 `/phone/ws` |
| 02 | 8장 | 모바일 자동화: uiautomator2·에뮬레이터 → 안드로이드 접근성 서비스(워커 앱, Java). 브라우저 자동화 행은 뮤즈 대체로 불필요 |
| 02 | 9장 | ADR-9 추가(아래). ADR-7(에뮬레이터 별도 VM)·ADR-8의 "봇마다 전용 AVD"는 대체됨 |
| 03 | 7·8·9장 | 세 어댑터의 자동화·로그인·스냅샷·기동 모드 항목을 6장 흐름과 휴대폰 요건으로 교체 |
| 03 | 6장 디렉터리 | `adapters/phone/`(원격 손 클라이언트, 기기 잠금, 게이트웨이 서버) 추가. `android_base.py`는 에뮬레이터 개발용으로 남기거나 원격 손 구현으로 바꾼다 |
| 06 | 1·2장 | P2 완료 기준(콜드 부팅 스모크)·P3(전용 AVD)·P4(VPN 사이드카)를 "휴대폰 워커" 단계로 재편(9장) |
| 레포 | — | `phone/`(워커 앱 소스) 추가. 지금의 `tools/phone-probe`가 출발점 |

바뀌지 않는 것: `ask`·`status` 입출력 스키마, AskResult 오류 필드 원칙, 허브 WebSocket 이벤트, 러너 인터페이스, 오케스트레이터 "금지" 절, `bots.yaml` 형식(주소만 게이트웨이로).

**ADR-9 (초안)**: 세 봇은 사용자 휴대폰의 워커 앱이 접근성 서비스로 조종하고, 워커는 허브에 아웃바운드 WebSocket으로 붙는다. 배경: 실측에서 에뮬레이터 대비 ask가 약 4배 빠르고(2분 → 30초), 에뮬레이터 VM·VPN이 필요 없으며, 세 앱 모두 실제 휴대폰에서 이미 로그인·알림이 동작한다. 대가: 휴대폰이 켜져 있고 잠금이 풀려 있어야 하며(전용 공기계 권장), 사이드로드 APK와 접근성 권한을 관리해야 하고, 허브가 공개 주소를 가져야 한다.
