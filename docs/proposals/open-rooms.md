# 제안: 열린 방 (사람 여러 명 + AI 여러 개가 직접 말하는 방)

상태: **폐기** (2026-11-27). R1~R4 구현·운영 배포까지 했다가 사용자 결정으로 코드와 테이블을 모두 지웠다(PR #7 되돌림, 마이그레이션 b5c6d7e8f9a0). 기록용으로만 남긴다.
참고한 외부 사례: 셋톡(chat.gonipro.app)의 공개 동작 — 참가자별 링크 키, 주기적 읽기·쓰기 API, 팀장 AI.
코드·디자인·이름은 가져오지 않는다. 동작 방식만 참고한다.

## 1. 왜

지금 허브는 **운영자 1명 + Claude 사회자** 구조다. 비서들은 Claude가 어댑터로 불러야만 말한다.
바깥 Agent는 `/api/inbox`로 글을 넣을 수 있지만, 토큰 하나를 모두 같이 쓰고 넣은 글은 Claude 실행을 일으킬 뿐이다.

원하는 것:
- 지인·팀원(사람)을 링크로 초대해 같은 방에서 대화
- 클로드 코드·코덱스·제미나이·피클 등 각 Agent가 **자기 이름으로 직접** 방을 읽고 쓴다
- 토론이 난장판이 되지 않게 순서를 정리하는 역할(팀장)을 둔다

## 2. 범위 (1차)

| 넣는 것 | 빼는 것 (나중) |
|---|---|
| 열린 방 생성·이름 바꾸기·닫기 | 구글 로그인, 기기 간 방 목록 동기화 |
| 참가자: 사람 / AI. 참가자마다 개별 키 | 서버가 API 키로 AI를 직접 부르는 "바로 답하기" |
| 사람 초대 링크(이름만 쓰고 입장) | 슬랙·Discord 연동 |
| AI용 읽기·쓰기 API (`/api/p/msgs`, `/api/p/send`) | 사진·파일 첨부 |
| 참가자 키 재발급·끊기 | 대화 자동 삭제 정책 |
| 팀장 지정(기존 Claude 사회자를 팀장으로 쓸 수 있음) | 결제·후원 |
| 웹 화면: 참가자 패널, 부르는 말(Agent 붙여넣기 문구) 복사 | |

## 3. 핵심 설계

### 3.1 데이터
- `room` : 열린 방. 기존 `session`과 별도 테이블(기존 1인 방 동작을 건드리지 않기 위해).
- `participant` : `id, room_id, kind(human|ai), name, key_hash, role(member|leader), check_every_s, enabled, last_seen_at`
  - 키는 원문을 저장하지 않고 해시만 저장. 원문은 발급 순간 한 번만 보여 줌.
- `room_message` : `id(방 안 단조 증가), room_id, participant_id, text, created_at`

### 3.2 AI 참가자 API (키 = 신원)
```
GET  /api/p/msgs?since=<id>     헤더 x-key: <참가자 키>
  → {me, room, check_every_s, msgs:[{id, who, kind, text, ts}]}
POST /api/p/send                헤더 x-key
  {text}  → {id}
```
- 키가 곧 그 참가자다. 다른 이름으로 쓸 수 없다(현재 inbox의 `from` 자기신고 문제 해결).
- 속도 제한: 참가자별 분당 읽기 12건·쓰기 10건(HUB_ROOM_READS_PER_MINUTE·HUB_ROOM_SENDS_PER_MINUTE), 넘으면 429 + retry_after_s. 권장 확인 간격 check_every_s 는 15~3600초.
- 키 재발급 시 예전 키 즉시 무효.

### 3.3 사람 참가자
- 초대 링크 `https://<허브>/#/join/<초대 키 ri_…>` 를 누르면 이름 입력 → 사람 참가자로 개인 키 발급 → 그 브라우저 localStorage 에 저장.
  - 초대 키를 `#` 뒤에 두어 서버 접근 로그에 남지 않게 한다. 서버에는 해시만 저장(`room.invite_hash`).
  - 링크를 새로 만들면 예전 링크는 바로 막힌다. [링크 끄기]로 초대를 닫는다.
  - 사람도 AI 와 같은 `/api/p/*` 로 읽고 쓴다(신원 체계 하나). 방 정원 20명, 링크 입장 분당 5회.
  - API: `GET /api/join/{invite}` 방 이름·참가자, `POST /api/join/{invite} {name}` 입장.
- 운영자(TOTP 로그인)는 지금처럼 전체 관리. 화면 `#/rooms` 에서 운영자 이름으로 글을 쓴다(`POST /api/rooms/{id}/messages`).
- 초대받은 사람은 그 방만 본다. 참가자 목록은 `GET /api/p/participants`.

### 3.4 팀장(순서 정리)
- 방 설정 "AI는 부를 때만"(`room.call_only`, `PATCH /api/rooms/{id} {call_only}`).
  - 참가자 읽기 응답의 각 글에 `to_me`(나를 @이름·@모두 로 불렀는지), 응답에 `my_turn`(내 마지막 글 이후 답 안 한 부름이 있는지)을 붙인다.
  - 켜진 방에서 **팀장이 아닌 AI** 가 부름 없이 보내면 허브가 `409 not_called` 로 막는다(사람·팀장은 제한 없음). AI 가 규칙을 안 지켜도 순서가 지켜진다.
  - 부름 판정은 이름 경계까지 본다(`@클로` 가 `@클로드` 에 걸리지 않음).
- 팀장 실행기 `hub/app/room_leader.py` (`python -m app.room_leader`).
  - **설계와 다르게 함**: 기존 러너(오케스트레이터)를 쓰지 않고, 다른 참가자처럼 자기 키로 `/api/p/*` 만 쓰는 작은 실행기로 했다. 러너 인터페이스·오케스트레이터 프롬프트를 건드리지 않고, 팀장을 아무 PC 에서나 돌릴 수 있게 하려는 것.
  - 누구를 부를지는 그 PC 의 `claude -p`(구독)가 정한다. 답 첫 줄이 `@이름` 한 명이 아니면 덜 말한 AI 부터 차례로 부른다.
  - 사람이 글을 쓰면 시작 → 한 명씩 지목 → 지목한 AI 가 답하거나 `LEADER_REPLY_WAIT_S` 가 지나면 다음 → `LEADER_MAX_TURNS` 만큼 돌면 `결론:` 을 올리고 사람 글이 올 때까지 쉰다. 처음 읽기는 지난 대화를 맞추기만 한다.
  - 웹 참가자 패널에서 "팀장 AI" 로 넣으면 실행 명령(주소·키 포함)을 한 번 보여 준다.

### 3.5 Agent 붙여넣기 문구
참가자 패널의 [부르는 말 복사]가 만드는 문구: 주소·키·읽기/쓰기 방법·대화 규칙(짧게, 연속 3회 제한, "멈춰" 즉시 중지).
이미 만든 `C:\work\discord-bots\AGENT_JOIN_GUIDE.md`의 규칙을 재사용한다.

### 3.6 실제 Agent 붙이기 (R4)
- PC 의 AI CLI: `hub/app/room_agent.py` (`python -m app.room_agent`). 나를 부를 때(my_turn)만 최근 대화를 넘겨 답을 올린다.
  - Claude Code: 기본(`claude -p`). Codex: `AGENT_LLM_CMD='codex exec --skip-git-repo-check -s read-only -m <모델> -o {out} -'`.
  - ChatGPT 계정 Codex 는 설정 파일의 모델을 못 쓸 수 있다(`model is not supported`). 그럴 때 `-m` 으로 지원 모델을 준다.
- 링크만 여는 앱(폰 비서 등): `GET /api/p/read?k=`(글자 페이지: 내 차례·[나를 부름]·답하는 링크), `GET /api/p/say?k=&text=`(열면 올라감, 같은 글 1분 안 재열기는 한 번만).
  JSON API 도 `?k=` 를 받는다. 키가 주소에 들어가 접근 로그에 남을 수 있으니 믿는 앱에만 준다.
  링크 페이지의 바깥 주소는 `HUB_PUBLIC_URL`(compose 기본 `https://$PUBLIC_HOST`).
- 방 관리 CLI `python -m app.room_admin` (컨테이너 안): 운영자 로그인 없이 방·참가자·키 재발급·부를 때만 켜기.

## 5. 단계

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| R1 | 테이블·참가자 키·`/api/p/msgs`·`/api/p/send` | 계약 테스트: 키별 신원, 재발급 후 옛 키 401, 속도 제한 429 |
| R2 | 웹: 열린 방 화면·참가자 패널·초대 링크·부르는 말 복사 | E2E: 사람 2명 + 스크립트 AI 1개가 한 방에서 대화 |
| R3 | 팀장 실행기(claude -p) 연결, "부를 때만" 모드 | AI 3개 토론에서 지목 순서대로만 답함 5회 중 4회 → 테스트 5회 모두 통과, 실제 claude -p 스모크 1회 통과 |
| R4 | 실제 Agent 붙이기(클로드 코드·코덱스·피클 등) | 사람이 스모크 → 운영 허브에서 팀장(claude)·클로(claude)·익스(codex) 토론 확인. 폰 앱 비서는 사람 확인 남음 |

## 6. 위험·한계
- 외부 공개 시 링크 키 유출 = 사칭. 키 재발급·끊기 버튼 필수, 키는 해시 저장.
- 폰 앱 비서(피클 등)가 주기적으로 HTTP를 부를 수 있는지는 앱마다 다르다. 안 되면 기존 폰 워커 어댑터가 대신 읽고 써 주는 경로가 필요(R4에서 확인).
- 지인·팀 사용이므로 개인정보·보관 기간 안내 문구 필요.
