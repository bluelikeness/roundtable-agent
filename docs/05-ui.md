# 멀티봇 UI 설계

> 작성일 2026-11-08

## 1. 화면 구성

화면은 하나다. 왼쪽 세션 목록, 가운데 대화, 오른쪽 봇 상태. 설정·계정 연결은 오른쪽 패널에서 열리는 시트로 처리하고 별도 페이지는 두지 않는다.

> 그림: 채팅 화면 와이어프레임 · 3기둥 (원본은 claude.ai 문서에만 있음)

| 영역 | 내용 | 너비 (데스크톱) |
| --- | --- | --- |
| 세션 목록 | 세션 제목, 마지막 메시지 시각, 실행 중 표시, 새 세션 버튼 | 240px, 접기 가능 |
| 대화 | 말풍선 스트림, 헤더에 세션 제목과 실행 상태("실행 중 · 2/3 응답"), 하단 입력창 | 나머지, 최대 너비 880px |
| 봇 상태 | 봇별 연결·큐·평균 응답 시간, 재로그인 버튼, Claude Code 로그인 상태와 오늘 실행 횟수 | 260px, 접기 가능 |

대화 영역이 항상 중심이다. 봇 상태는 시선을 끄는 색을 쓰지 않고, 문제가 있는 봇만 경고색으로 뜨게 한다.

## 2. 말풍선 종류와 표시 규칙

| 종류 | 출처 이벤트 | 위치·모양 | 머리글 | 본문 |
| --- | --- | --- | --- | --- |
| 사용자 | 입력 | 오른쪽, 강조색 테두리 | 없음 | 입력 그대로 |
| Claude 노트 | `claude.note` | 왼쪽, 테두리 없음, 작은 회색 글씨 | "Claude ·" 접두 | 한두 줄. 길면 접힘 |
| 봇 원문 | `bot.reply` | 왼쪽, 봇 고유색 테두리·옅은 배경 | 봇 이름 · 소요 초 | `raw` 전문 + structured 요소. 20줄 넘으면 "더 보기" |
| 봇 대기 | `bot.pending` | 왼쪽, 봇 고유색 점선 테두리 | 봇 이름 · 경과 초(실시간) | "응답 중…". 큐 대기면 "대기 n번째" |
| 봇 오류 | `bot.reply` with `ok=false` | 왼쪽, 경고색 | 봇 이름 | 사유 한 줄 + 재로그인·재시도 버튼 |
| Claude 정리 | `claude.final` | 왼쪽, 강조색 테두리·배경, 폭 넓게 | "Claude 정리" | 마크다운(표·목록) + 다음 행동 버튼 |
| 실행 실패 | `run.failed` | 가운데, 경고색 띠 | — | 사유 + "다시 시도" |
| 시스템 | 세션 분할·봇 비활성 등 | 가운데, 회색 한 줄 | — | "새 Claude 세션으로 이어집니다" |

**순서**: `message.seq` 기준. 팬아웃에서 봇 원문은 도착 순서로 쌓이고, 대기 말풍선은 `bot.pending` 시점에 자리를 잡아 `bot.reply`가 오면 그 자리에서 교체된다. 사용자가 봇별 순서를 예측할 수 있게 자리 바꿈은 하지 않는다.

**봇 색**: 허브 `bots.yaml`의 `color`. 지정 없으면 봇 순서대로 팔레트. 같은 봇은 세션 전체에서 같은 색.

**Claude 정리 안의 버튼**: 정리 마지막 줄이 "진행할까요?"류 확정 질문이면 UI가 `[진행]` `[취소]` 버튼을 붙이고, 누르면 입력창에 "진행해"·"취소"를 넣어 전송한다. 버튼은 입력을 대신 쓰는 것일 뿐 별도 API가 아니다.

**타임스탬프**: 말풍선 머리글에는 소요 초만, 절대 시각은 hover/롱프레스 툴팁.

## 3. structured 렌더링

봇 원문 말풍선 안에서 `raw` 아래에 순서대로 그린다. `raw`에 이미 `[버튼: X]` 표기가 있으므로 structured 요소는 보조이고, 못 그려도 정보는 남는다.

| 요소 | 표시 | 동작 |
| --- | --- | --- |
| `buttons[]` | 봇 색 테두리의 작은 칩, 가로 나열 | 클릭 → 입력창에 `@<봇> [tap:<action_id>]` 채워 전송. 직전 응답이 아니면(세션에 더 새로운 봇 응답이 있으면) 비활성 + 툴팁 "만료됨" |
| `choices[]` | 칩, `buttons`와 같은 모양이나 회색 | 클릭 → 입력창에 `@<봇> <선택지 텍스트>` |
| `links[]` | 제목 링크 목록 | 새 탭 |
| `cards[]` | 제목·부제·본문·썸네일의 가로 스크롤 카드 | 카드의 `url`은 새 탭. 썸네일은 이미지 프록시 |
| `images[]` | 썸네일 그리드, 클릭 시 확대 | 이미지 프록시 |
| `confirmation_required` | 말풍선 밖 아래에 강조색 박스: 요약 + "이 작업은 확인이 필요합니다" | 박스 자체에는 버튼 없음. 확정은 Claude 정리의 `[진행]`으로만 |

**이미지 프록시**: 어댑터가 저장한 이미지 경로(`/data/images/<id>.jpg`)는 어댑터 컨테이너 안이다. 허브 API가 `GET /api/bots/<bot>/images/<id>`로 어댑터 관리 HTTP의 `GET /images/<id>`를 프록시한다(허브 로그인 필요, 어댑터 토큰은 허브만 보유). UI는 허브 URL만 안다. 어댑터 쪽 엔드포인트는 어댑터 명세 5장 `GET /images/<id>`.

**`raw` 안의 마크다운**: 봇 원문은 마크다운으로 해석하지 않는다. 뮤즈처럼 마크다운을 쓰는 봇이 있어도 텍스트 그대로. 해석하면 봇별로 다르게 보여 원문 보존 원칙과 어긋난다. 줄바꿈과 URL 자동 링크만 적용.

## 4. 봇 상태 패널과 계정 연결

**패널 행** (봇마다)

| 요소 | 값 출처 | 표시 |
| --- | --- | --- |
| 상태 점 | `bot.available` · `enabled` | 초록 연결, 노랑 로그인 필요·쿨다운, 회색 비활성, 빨강 backend\_down |
| 이름 · 상태어 | `bot.reason` | "연결", "응답 중", "로그인 필요", "비활성", "점검 필요" |
| 부제 | `last_ok_at`, `queue_depth`, `avg_latency_ms` | "마지막 응답 1분 전", "큐 1 · 평균 52초" |
| 버튼 | 상태별 | 로그인 필요 → `재로그인`, 연결 → `⋯` 메뉴(비활성화·대화 초기화·로그 보기), 비활성 → `활성화` |

패널 하단에 Claude Code 섹션: 로그인 정상 여부, 오늘 실행 횟수, 오늘 토큰(usage 합). 로그인이 깨지면 빨강 + "러너 컨테이너에서 `claude login` 필요" 안내. 웹에서 Claude Code 로그인을 대신 해주지 않는다(약관·보안).

**재로그인 시트** (패널 위로 슬라이드)

| 어댑터 흐름 | 시트 내용 |
| --- | --- |
| `CodeLogin` (Vooy) | 1단계 "텔레그램으로 코드를 보냈습니다" + 코드 입력 → 2단계 필요 시 비밀번호 입력 → 완료 |
| `VncLogin` (뮤즈·피클) | noVNC iframe(허브가 프록시, 허브 로그인 필요) + "로그인을 마치면 완료를 누르세요" + `완료` 버튼 → 어댑터 `/login/complete` 호출 → 결과 표시 |

시트는 `POST /api/bots/<bot>/login/start`의 응답(`flow`)으로 어느 쪽을 그릴지 정한다. UI에 봇별 분기를 두지 않는다.

**로그 보기**: 어댑터 `GET /logs`를 허브가 프록시. 최근 ask 20건의 시각·입력 앞 40자·`ok`·`latency_ms`·`error`. 디버깅용이라 꾸미지 않는다.

## 5. 세션 목록과 입력창

**세션 목록**

- 최신 활동순. 각 항목: 제목, 마지막 메시지 시각, 실행 중이면 점 애니메이션.
- 제목은 첫 사용자 메시지 앞 20자. 더블클릭(모바일 길게 누르기)으로 이름 변경, `⋯` 메뉴에서 삭제·보관.
- "+ 새 세션" 버튼. 빈 세션은 첫 메시지 전까지 DB에 만들지 않는다.
- 세션 전환 시 대화 영역은 `GET /api/sessions/<id>/messages`로 전부 로드(세션당 수백 건 수준, 페이지네이션은 1,000건 넘을 때만).

**입력창**

- 여러 줄 입력, Enter 전송, Shift+Enter 줄바꿈. 모바일은 전송 버튼만.
- `@` 입력 시 봇 별칭 자동완성(허브 `bots.yaml`). 선택하면 ` @Vooy  ` 삽입. 이는 텍스트일 뿐이고 해석은 Claude가 한다(오케스트레이터 3장).
- 실행 중(`run.status=running`)에도 입력 가능. 전송하면 `queued`로 들어가고 입력창 위에 "이전 요청 처리 중 — 대기 1" 표시. 큐 취소 버튼 제공.
- 슬래시 명령 (UI가 직접 처리, Claude에 안 감):

| 명령 | 동작 |
| --- | --- |
| `/new` | 새 세션 |
| `/reset <봇>` | 해당 봇 대화 초기화 (어댑터 `/reset`) |
| `/restart` | 현재 허브 세션의 Claude Code 세션을 새로 시작 (요약 주입) |
| `/model opus` \| `sonnet` | 다음 실행부터 모델 변경, 세션에 저장 |
| `/stop` | 실행 중인 run 중단 (러너 SIGTERM) |

명령 외 텍스트는 전부 Claude에게 간다. 명령 인식 실패를 막기 위해 자동완성 목록을 `/` 입력 시 띄운다.

## 6. WebSocket 프로토콜

연결은 로그인 후 하나(`/ws`). 세션 구독은 메시지로 바꾼다. 모든 이벤트는 `{type, session_id, seq, ts, payload}` 봉투다. `seq`는 세션 안에서 단조 증가하고, 재연결 시 클라이언트가 마지막 `seq`를 보내면 그 이후를 재전송한다.

**클라이언트 → 서버**

| type | payload | 비고 |
| --- | --- | --- |
| `subscribe` | `{session_id, since_seq}` | 세션 전환·재연결 |
| `send` | `{text, model?}` | 사용자 메시지. 응답은 `message.ack` |
| `cancel_queued` | `{run_id}` | queued 상태만 취소 가능 |
| `stop_run` | `{run_id}` | running 중단 |

**서버 → 클라이언트**

| type | payload | UI 상태 전이 |
| --- | --- | --- |
| `message.ack` | `{message_id, run_id, status: queued\|running}` | 사용자 말풍선 확정, 헤더 "실행 중" 또는 "대기 n" |
| `run.started` | `{run_id, claude_session_id}` | 헤더 "실행 중", 입력창 위 안내 |
| `claude.note` | `{run_id, text}` | 노트 말풍선 추가 |
| `bot.pending` | `{run_id, bot, tool_call_id, queue_position}` | 대기 말풍선 추가, 헤더 카운터 "0/3 응답" |
| `bot.reply` | `{run_id, bot, tool_call_id, ok, raw, structured, needs_input, error, latency_ms, message_id}` | 대기 말풍선을 원문·오류 말풍선으로 교체, 카운터 증가 |
| `claude.final` | `{run_id, text, message_id, usage}` | 정리 말풍선, 헤더 "완료", 확정 질문이면 버튼 |
| `run.finished` | `{run_id, status: done\|failed\|timeout, error?}` | failed·timeout이면 실패 띠. 큐에 다음 run 있으면 자동 시작 |
| `bot.status` | `{bot, available, reason, last_ok_at, queue_depth, avg_latency_ms, enabled}` | 상태 패널 갱신. 세션 무관(session\_id null) |
| `session.system` | `{text}` | 시스템 한 줄 말풍선 (세션 분할 등) |

**지속성과 복구**: 모든 서버 이벤트는 먼저 DB(`message`·`run`·`tool_call`)에 쓰고 그다음 전송한다. 새로고침하면 REST로 전체 로드 후 `subscribe since_seq`로 이어 붙인다. 실행 중 새로고침해도 대기 말풍선이 복원되도록 `tool_call`에 `started_at`만 있고 `output`이 없는 행을 pending으로 그린다.

**경과 초 타이머**: 서버가 초마다 보내지 않는다. 클라이언트가 `bot.pending.ts` 기준으로 로컬 계산.

## 7. 로그인·모바일·접근성

**로그인**: 운영자 계정 하나. 아이디·비밀번호 + TOTP(인증 앱). 세션 쿠키 `HttpOnly; Secure; SameSite=Strict`, 유효 7일, 활동 시 연장. 로그인 전에는 `/login` 외 모든 경로가 302. 5회 실패 시 15분 잠금. 비밀번호 변경·TOTP 재설정은 러너 컨테이너의 CLI(`hub-admin reset-password`)로만, 웹에 두지 않는다.

**모바일 (≤ 768px)**

- 대화 영역만 전체 화면. 세션 목록은 왼쪽 드로어, 봇 상태는 헤더의 상태 점 3개를 탭하면 바텀 시트.
- 헤더 상태 점: 봇별 색 점 + 문제가 있으면 느낌표 배지. 실행 중이면 헤더에 "2/3" 카운터.
- 입력창은 키보드 위에 고정, `viewport-fit=cover`와 safe-area 패딩.
- 봇 원문 말풍선은 10줄에서 접기. 카드는 세로 스택.
- noVNC 재로그인 시트는 가로 모드 권장 안내만 띄우고 막지 않는다.

**접근성**

- 말풍선 종류를 색에만 의존하지 않는다: 머리글 텍스트(봇 이름·"Claude 정리")가 항상 있다.
- 대기 말풍선은 `aria-live="polite"`, 정리 말풍선 도착은 `aria-live="assertive"` 한 번.
- 키보드: Tab 순서는 입력창 → 전송 → 최신 말풍선의 버튼들. `Esc`로 시트 닫기.
- 다크 모드: 시스템 설정 따름, 토큰 기반 색상.

## 8. 컴포넌트 구조와 상태 관리

```
src/
  app/            App, Router(/login, /), AuthGuard
  api/            rest.ts (fetch 래퍼), ws.ts (연결·재연결·seq 추적), types.ts (서버 Pydantic에서 생성)
  store/          zustand: sessions, messages(by session), runs, bots, ui(drawer/sheet)
  features/
    sessions/     SessionList, SessionItem, NewSessionButton
    chat/         ChatView, MessageList, bubbles/{User,Note,BotReply,BotPending,BotError,Final,System}
                  Composer(입력창, @자동완성, /명령), RunHeader(실행 상태)
    structured/   Buttons, Choices, Links, Cards, Images, ConfirmBox
    bots/         BotPanel, BotRow, LoginSheet(CodeLogin, VncLogin), BotLogs
  lib/            time(경과 초), markdown(Claude 정리만), colors(봇 팔레트)
```

**상태 원칙**

- 서버가 진실. 스토어는 이벤트 리듀서일 뿐이고 낙관적 갱신은 사용자 말풍선 하나만(ack 전까지 회색).
- `messages[session_id]`는 `seq` 정렬 배열. `bot.pending`은 `tool_call_id`를 키로 한 자리표시자 메시지로 넣고, `bot.reply`가 같은 키로 교체.
- `runs[session_id]`는 현재 run과 queued 목록. 헤더·입력창 안내가 여기서 파생.
- `bots`는 세션 무관 전역. `bot.status` 이벤트로만 갱신, 폴링 없음.
- 타입은 서버의 Pydantic 이벤트 모델에서 `datamodel-codegen`으로 TS 생성. 프로토콜 변경 시 양쪽이 동시에 깨지게 한다.

**테스트**: 스토어 리듀서는 이벤트 시퀀스 고정 입력 → 스냅샷. 말풍선 컴포넌트는 Storybook 없이 vitest + testing-library로 종류별 렌더 확인. E2E는 Mock 어댑터 + 실제 허브로 Playwright 시나리오 5개(T2·T3·T7·T8·T10과 대응).
